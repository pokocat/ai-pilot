## 一、今日攻守签（#5）—— 每日回访锚点

### 1.1 定位与心理杠杆

把黄历这个千年验证过的日活产品**个人化**后装进军师世界观。每天一张按命主流日推演的
「今日签」，打开即领——领签本身就是回访动作，不另设空洞签到。
杠杆：可变奖励（每日签面不同）+ 仪式感（拔签）+ 连续性（领签 streak）。

### 1.2 推演引擎（纯规则，零 LLM）

- 输入：命主八字（paipan v2 现成）+ 当日流日干支（lunar 库现成）。
- 规则：流日天干地支与命主用神/忌神生克 → 三态判定：
  - **攻**（用神得力）/ **守**(忌神当令) / **平**（无明显生克）。
- 派生字段：
  - `verdict`: gong | shou | ping
  - `tags`: 宜/忌各 1-2 项，从固定池选（签约·谈判·招人·发布·催款·大额支出·动土·出行）
  - `luckyHour`: 吉时（时辰名 + 现代时段，如「巳时 · 上午九至十一点」）
  - `aphorism`: 一句签语，从献策池按 verdict 分桶轮换（复用 sayings 运营位）
- 确定性：同人同日结果恒定（免缓存争议）；无时辰按 paipan v2 缺时辰口径降级并标注。

### 1.3 界面与交互

1. **军情 tab 顶部 · 签筒卡**（home/index.tsx，位于三势卡上方）
   - 未领态：直角案卷卡，签筒图形 + 「今日一签，未启」+ 按钮「领签」。
   - 已领态：压缩为一行横条：`攻 · 宜签约 忌大额支出 · 巳时吉` → 点击进签详情页。
2. **签详情页**（`packages/work/sign/index.tsx`）
   - 领签动画：竹签自签筒抽出（300ms 位移+渐显，弱动效，不做摇一摇）。
   - 签面（自上而下）：大字「攻/守/平」（本命色/danger/ink-2）→ 签语一句 →
     宜/忌两列 → 吉时 → 底部一行小字「依你命盘流日推演 · 仅作节奏参考」。
   - 出图分享：复用 cards 管线，新增 `POST /cards/sign`（含小程序码回流位）。
3. **连续领签**：签面底部「连领 N 日」。与复盘 streak（reviewStreak）**口径分开**，
   各自展示，不合并（复盘是重行为，领签是轻行为，混了会稀释复盘的分量）。

### 1.4 文案（军师语感）

- 攻日：「今日锋芒在外。宜主动出击，谈那件你拖着的事。」
- 守日：「今日藏锋。整军、清账、练内功，不宜出征。」
- 平日：「今日无风无浪。按你的三步走，稳步推进即可。」
- 缺时辰：「你的时辰未补，这支签只看到七分。补全生辰，我看得更透。」

### 1.5 数据与接口

```prisma
model DailySignClaim {
  id        String   @id @default(cuid())
  userId    String
  dateKey   String   // "2026-07-25"（Asia/Shanghai 口径，防 UTC 跨日错位）
  verdict   String
  createdAt DateTime @default(now())
  @@unique([userId, dateKey])
}
```

- `GET /daily-sign` → 当日签面（无副作用，未领也可预览签筒态）
- `POST /daily-sign/claim` → 落 claim + 返回签面与 `claimStreak`
- `GET /daily-sign/streak` → 连领天数（连续 dateKey 计算，同 reviewStreak 写法）

### 1.6 接线与防呆

- 命理开关（profile 现有 gating）关闭时整卡不渲染。
- 无生辰 → 签筒卡变引导卡「补生辰，启今日签」→ 跳命盘补录流程（mingpan 已有）。
- 时区：dateKey 一律按 Asia/Shanghai 生成（吸取 weeklyReviewReminderScan 时区教训）。
- M2 再接推送：并入早间军情简报（morning job），此期不单独申请模板。

### 1.7 指标与分期

- 指标：领签率（DAU 口径）、连领≥7 人数、签详情→复盘/对话的导流率。
- M1：引擎+签筒卡+详情页+claim/streak。M2：出图分享、并入晨报推送。

## 二、预言揭封日（#1）—— 应验事件

### 2.1 定位与心理杠杆

后端 `prophecy-due-scan` 已每 6h 找出到期预言，目前只写审计行、等用户下次复盘才带出。
本设计把它变成**事件**：到期 → 触达 →（回来）→ 揭封 → 对照 → 命中卡。
杠杆：可变奖励（命中与否事先未知）+ 蔡格尼克效应（封着的信必须拆）+ 社交货币（命中卡）。

### 2.2 核心循环

```
军师给出可验证判断 ─→ 系统登记（现有）─→ dueDate 到期（现有 scan）
      ↑                                        │
      │                              推送「有一道预言，今日应验」（新）
      │                                        ↓
  命中率回写天机账本 ←── 军师判词 ←── 用户揭封+回填结果（新）
```

### 2.3 界面与交互

1. **入口**：军情 tab「天机」卡：火漆信封图形 + 「待揭封 · N 道」；
   问策 tab 会话列表总军师置顶行同步小红点（复用 unread 机制）。
2. **揭封页**（`packages/work/prophecy/index.tsx`）
   - 信封态：米纸信封、火漆印（本命色）、封条写登记日期与「应验之期已至」。
   - 点击「揭封」→ 封蜡裂开动效 → 展开预言原文 + 当时依据 + 判定口径（登记时三要素）。
   - 回填：三选一「应验了 / 未应验 / 说不清」+ 一句话实际情况（选填）。
   - 军师判词（规则模板，不走 LLM）：
     - 命中 → 生成**命中卡**（`POST /cards/prophecy`）：predictions 原文 + 登记日 + 应验日 + 「料事如神」章。
     - 未命中 → 「天时是概率不是定数。这次没应验，说明你的人谋胜了天时。」
     - 说不清 → 「留着。有些账要再走一程才看得清。」
3. **揭封后**：命中率进天机账本注入块（复盘时军师引用真实数字）；触发战功「料事如神」（首中）。

### 2.4 数据与接口

```prisma
// ProphecyLog 增列（现有表，schema.prisma:1247 附近）
revealedAt   DateTime?
outcome      String?   // hit | miss | unclear
outcomeNote  String?
```

- `GET /prophecies?status=due|revealed` → 列表（信封态所需字段）
- `POST /prophecy/:id/reveal` `{outcome, note?}` → 幂等（已 reveal 则 409）
- 推送：`prophecy-due-scan` 内、打 `dueNotifiedAt` 的同时调
  `sendWechatSubscribeMessage(scene: 'review', …)`——**依赖 review 模板**（当前缺失）。
  M1 先只做站内（红点+天机卡），模板到位后开推送，代码留好开关
  `PROPHECY_REVEAL_PUSH=on|off`。

### 2.5 授权时机（一次性订阅额度策略）

微信订阅消息一次授权一发。在**登记预言的当口**索权最顺：军师说完「这事三个月见分晓」，
界面出「应验之日，报你一声」按钮 → `requestWechatSubscribe('review')`。
复盘完成后可再补一次批量索权（复用 studio 现有订阅入口）。

### 2.6 防呆与红线

- 不挂任何货币奖励：揭封只兑现叙事（命中卡/判词/账本），乱填无利可图。
- 到期 30 天未揭封 → 保留现行为：复盘时军师带出（scan 已有），信封不过期不消失。
- 判词严守数字铁律：命中率只引账本，样本 <5 不报百分比。

### 2.7 指标与分期

- 指标：揭封率（到期→7 日内揭封）、推送→打开转化、命中卡分享率。
- M1：揭封页+回填+判词+命中卡（站内触发）。M2：review 模板推送、战功接线。

## 三、命运叙事线 · 章回连载（#3）—— 长线剧情

### 3.1 定位与心理杠杆

V6.0 的命运叙事线只在年度复盘更新，太稀疏。改成**每月复盘产出一回章回体**，
老板的经营史成为一部每月更新的连续剧；下一回回目提前预告=制度化的悬念钩子。
杠杆：叙事传输 + 连载悬念 + 沉没成本（弃剧成本逐月上升）。

### 3.2 生成机制

- 触发：月复盘完成时（现有月复盘流程尾部挂钩子），走 structured output：

```ts
type NarrativeChapter = {
  seq: number          // 第 N 回
  title: string        // 章回体回目：对仗双句，如「断腕求生砍产线，秋风未起先备粮」
  body: string         // 300-500 字本月剧情：关键决策、低谷、转折；引用账本真实事件
  teaser: string       // 下回预告：半句回目或一句悬念，指向真实待验证事项（预言/军令状）
  monthKey: string     // "2026-07"
}
```

- 素材注入：当月决策账本 + 天机账本 + 复盘账本 + 战略档案（现有注入通道，schema.ts:181）。
- 首回：从战略档案里的叙事线初稿迁移生成「楔子 + 第一回」。
- 铁律：body 只引用账本真实事件；teaser 必须指向系统能兑现的事（有 dueDate 的预言、
  下月复盘），不开空头支票——这是 V6.0 悬念钩子约束的产品化解法。

### 3.3 界面与交互

1. **入口**：老板 tab 档案组新增「命运叙事线 · 连载中」（列于命盘报告旁），
   副题显示最新回目；有新回未读时缀朱点。
2. **连载页**（`packages/work/narrative/index.tsx`）
   - 竖排卷轴列表：楔子、第一回、第二回……每回一张直角案卷条（回目 + 月份）。
   - 回详情：回目大字居中 → 正文（宋体正文排版）→ 尾部「下回预告」：
     烫金半掩样式（文字露一半，遮罩渐隐），落款「军师 · 记于 YYYY 年 X 月」。
   - 缺月处理：某月未做月复盘 → 列表占位条「此月无战事记载」（轻损失厌恶，不惩罚）。
3. **分享**：回详情可出图（`POST /cards/chapter`，卷轴纵版）。
4. **年度合订**：年度复盘时 12 回装订进 A 级年度报告（战史卷轴），M3。

### 3.4 数据与接口

```prisma
model NarrativeChapter {
  id        String   @id @default(cuid())
  userId    String
  seq       Int
  monthKey  String
  title     String
  body      String   @db.Text
  teaser    String
  readAt    DateTime?
  createdAt DateTime @default(now())
  @@unique([userId, monthKey])
}
```

- `GET /narrative` → 章回列表（含未读标记）；`GET /narrative/:seq` → 详情（写 readAt）
- 生成挂在月复盘完成事件里异步执行（复用 deliverable 异步管线），失败静默重试，
  不阻塞复盘主流程。

### 3.5 防呆与红线

- LLM 输出过内容安全（复用现有 moderation 通道）；涉命理措辞按合规口径。
- 回目/正文禁 AI 腔与咨询黑话（提示词沿用禁用词表）。
- 用户改了行业/战略方向 → 不回写旧回目（历史即历史），新回自然转折。

### 3.6 指标与分期

- 指标：月复盘完成率变化（核心——连载是否反向拉动复盘）、回详情阅读率、出图分享率。
- M1：生成+连载页+未读朱点。M2：出图、teaser 接推送。M3：年度合订本。

## 四、军师懂你指数（#10）—— 投入可视化

### 4.1 定位与心理杠杆

把 V6.0 的「自进化」（决策模式画像、战略档案沉淀）从暗处搬到明处：用户每一次复盘、
回填、预言验证都在喂养一个**看得见涨**的指数，指数档位解锁「关于你自己的更深层分析」。
杠杆：禀赋效应（存进来的数据成为资产）+ 目标梯度（差 3 次复盘就解锁）+ 迁移成本可视化。

### 4.2 计分模型（纯派生，无新账本）

0-100 整数，服务端实时计算（可加 5 分钟缓存），构成公开透明：

| 维度 | 上限 | 口径（全部来自现有表） |
|---|---|---|
| 档案完整度 | 25 | 八字含时辰 10 / 行业+阶段 5 / KPI 基线回填 10 |
| 复盘积累 | 25 | 复盘总次数对数曲线（10 次≈15 分，40 次封顶） |
| 数据回填 | 15 | 经营数据回填点数 |
| 决策日志 | 15 | 已登记决策条数（含已验证加权 ×1.5） |
| 预言验证 | 10 | 已揭封条数（与 #1 联动） |
| 相处时日 | 10 | usageDays 对数曲线 |

- **只升不降**（快照取历史峰值），绝不惩罚；展示用**中文成数**：
  分数四舍五入到成（34 分→「三成」），两端用称谓——低于 20 曰「初识」，80 及以上曰「知根知底」。

### 4.3 档位解锁（LLM 生成，账本注入，生成后缓存为交付物）

| 档位 | 解锁分析 | 内容来源 |
|---|---|---|
| 30 | 「你的决策风格初判」 | 决策账本快/慢决策分布 |
| 50 | 「你的冲动决策模式」 | 决策账本+紧急战况记录交叉 |
| 70 | 「你的能量节奏图」 | 复盘时间分布×命盘五行节奏 |
| 90 | 「决策盲区全谱」 | 全账本+档案综合推演 |

解锁不自动弹出——档位到了先出**封印卡**（「新密报已备 · 待你启阅」），点击才生成并展示，
保留"拆封"仪式感。样本不足时按数字铁律如实说（「这份还差些火候，再攒 N 次复盘」）。

### 4.4 界面与交互

1. **老板 tab · 懂你卡**（列于段位卡旁，无冷启动门槛——这是给新用户的第一根进度条）
   - 横向进度条（本命色渐进）+ 「军师对你的了解 · 三成」
   - 下一解锁提示一行：「再复盘 3 次 → 启「冲动决策模式」密报」
2. **详情页**（`packages/work/understanding/index.tsx`）
   - 构成明细六行（每行：维度名 + 已得/上限 + 一句怎么涨）；
   - 密报架：四格档位，未达=封印灰卡（显示差值），已达未启=火漆卡，已启=可重读。
3. **全局涨分反馈**：复盘/回填/揭封完成 toast 追加一行小字「军师对你的了解 +2」。

### 4.5 接口

- `GET /understanding` → `{score, tier, breakdown[], nextUnlock:{key,need,label}}`
- `POST /understanding/report/:key` → 生成/读取档位密报（幂等，生成后缓存）

### 4.6 防呆

- 无生辰/极新用户：score 照算（可能仅个位数），文案给路标不给挫败：
  「我们才刚认识。把生辰给我，把今天的仗跟我说说。」
- 密报内容严守数字铁律；禁"percent%"表述，一律成数。

### 4.7 指标与分期

- 指标：懂你卡点击率、解锁密报生成率、涨分行为（复盘/回填）频次变化。
- M1：计分+懂你卡+详情页。M2：档位密报生成、与 #1/#12 战功联动。

## 五、横切事项

1. **订阅消息**：payment/report 模板已配（见总档 §3）；**review 模板缺失**是 #1 推送与
   4 个提醒 job 的共同前置，优先申请（措辞走「复盘提醒/经营节奏提醒」类目）。
2. **调度**：无新增常驻 job；#1 复用 prophecy-due-scan，#3 挂月复盘事件，#5/#10 为拉取式。
3. **埋点**：四机制统一 AuditLog 事件前缀 `retention.*`（如 `retention.sign.claim`、
   `retention.prophecy.reveal`），后续 admin 留存看板直接聚合。
4. **建设顺序建议**：#5 → #1 → #10 → #3（先立日活锚点，再立应验事件，再资产化，最后长线剧情）。
