# 已发布服务迁入新集群 SOP

本流程来自军师正式迁移，适合作为后续服务的通用骨架。数据库、上传文件、登录态、支付和后台任务各有业务约束，每个服务必须独立完成盘点、改造和验收，不能直接复用军师的数据库名、账号、Redis DB、端口或资源 ID。

当前新集群采用 A 主用、B 常驻备用，ALB 权重 100/0。两边同版本、同数据库，B 持续接受独立健康检查。日常发布用滚动切流；起量后确认共享状态和连接预算，再开启双机分流。备用机权重 0 不提供自动故障接管，切换需操作 ALB。

## 1. 建立每个服务的迁移单

开始前记录并核对下表，线上状态以实际进程、配置、数据库与域名为准，不能只看代码默认值。

| 维度 | 必须确认的内容 | 完成标准 |
| --- | --- | --- |
| 发布范围 | 已正式发布的产品、API/BFF/后台/静态前端、独立发布边界 | 服务归属清楚；开发中的 ClassVibe 不纳入此次正式迁移 |
| 运行真相 | ECS 实例 ID/公网和内网 IP、端口、进程、当前 SHA、systemd/容器、Nginx 路由 | 核实用户请求实际落在哪；把旧机所有服务逐项列出 |
| 数据库 | 引擎和版本、编码/排序规则/时区、表/行/大小、序列、扩展、账号权限、连接池 | 明确是同引擎迁移还是异构改造，正式与测试使用不同库和账号 |
| 共享状态 | 进程内 session/权限/缓存/验证码/限流、长连接、幂等键 | 跨进程一致或每次读权威库；不依赖 ALB 粘滞来掩盖状态问题 |
| 文件 | 上传目录、模型缓存、浏览器/字体、证书、OSS 对象引用、临时文件 | 持久文件转 OSS 或完成同步；新机依赖齐全、权限正确 |
| 外部依赖 | 账号中心/JWKS/issuer/audience、支付/回调、视频底座、AI、短信、OSS、IP 白名单 | 从两台新机逐项验证；不因迁移修改用户身份、商户、运营配置 |
| 后台工作 | 定时任务、任务队列、锁、租约、扣费/退款/outbox、任务恢复 | 唯一调度或可靠选主；停止领单、等待任务完成；外部已受理任务先查询，不能重建或重复扣费 |
| 上线方式 | 域名/ALB 规则/后端组、TLS、探针、监控与日志、恢复动作 | 发布只能去新机；旧正式进程有迁移标记与启动拦截 |

军师和爱速拍 BFF 共用业务库，所以数据库与依赖需要协调迁移，发布目录仍保持独立。账号中心、AIStar 等要各自重新盘点，不能因军师已验证就认定它们无需改造。

## 2. 先改造与验证，再动正式数据

1. 固定已部署 SHA，与开发目录区分。保留所有既有未提交修改；归档固定提交，在独立目录构建，不覆盖运行中的 dist/node_modules。
2. 异构迁移逐项审查 ORM/Flyway/原生 SQL、类型、主键/自增序列、布尔/JSON/数组/二进制、日期与时区、NULL、大小写及唯一约束。不能用改连接串代替数据库兼容改造。
3. 为每个服务分配独立正式库、运行账号和测试库；运行账号不具备超级用户/建库权限。设置每进程连接池及角色总连接预算，计入主备、scheduler、测试与维护连接。
4. RDS 和 Tair 使用内网 TLS 与正确 CA，拒绝关闭证书校验。Tair 用于可丢失的缓存/限流等共享状态，业务账本仍在数据库；隔离不同产品的 key namespace/逻辑 DB。
5. API 关闭自带 scheduler，独立任务进程唯一运行；后台 worker 可停止领单并完成已领任务。上传、支付、幂等与任务租约要能跨实例恢复。
6. 用隔离测试库跑完整必要检查，包含真实数据库版本、并发/支付幂等、权限撤销与开通、服务 profile。浏览器/字体等依赖需要实渲染验证，不能只看依赖安装成功。
7. 在新机关闭正式流量闸门，先验收内部 API、ALB 两个地址的 SNI/TLS、不同域名和产品边界、401/403、前端深链与上传限制。只有过门后才进入切流窗口。

## 3. 配好新资源并完成数据演练

- ECS：安装固定运行时与缺失依赖；两个产品的安装目录与 EnvironmentFile 独立；配置只放受保护的 /etc 路径，不进归档、日志或仓库。给两台机器安装集群身份标记，验证 SSH IP 确实属于预期 ECS 实例。
- ALB：HTTPS、HTTP 跳转、合理长请求超时、后端就绪探针、健康阈值与连接排空；安全组只开放必要来源。按实际云探针地址配置，不能把资源成员 Available 当成健康检查通过。
- SLS：独立应用/访问日志、索引、保留期与机器组；从两台新机写入并实际查到日志，再认定采集成功。
- 监控：每个 API/BFF 实例单独抓取，保持既有 metrics 鉴权。定时任务、数据库、Tair 与外部依赖也要有适当观察方式。文件 bind mount 可能指向旧 inode，改配置后需核验运行中的配置和目标，不能仅凭 reload 返回成功。
- RDS：配置自动全量及日志备份，保留恢复窗口。容量按全部服务、索引/膨胀和增长估算，不能把当前单库大小当成长期上限。
- 首次全量导入仅进入演练库。核对表数、行数、主键/外键、关键金额、时间语义、序列、枚举、对象存储引用及内容指纹；再验证真实接口。测试不得使用正式账号或清库工具指向正式库。

## 4. 正式冻结、最终复制与切流

1. 明确恢复边界，备份源库、当前代码版本及路由配置；验证备份可读取/恢复。原数据库、原程序和其他应用都不删除。
2. 入口进入短维护窗口；等待在途请求与任务完成。停止旧正式写入进程，将源业务库设为只读，确认没有遗漏的 worker、回调或定时器继续写入。
3. 从冻结后的源库生成最终快照，计算校验和，恢复到新正式库。导入前核对目标库名与账号；不得覆盖另一个产品的库。
4. 对最终源/目标重复核对：行数、双内容指纹、关键金额/身份/状态、序列、时区/编码与约束。必须一致后才允许新库接收正式写入。
5. 启动新 A 的正式进程与唯一 scheduler；B 同版本启动待命，API 内的 scheduler 仍关闭。确认实际 PID 的环境、加载路径、数据库、Tair、profile、CA、端口，而非只看磁盘配置。
6. ALB A=100、B=0，打开新入口；核验旧 DNS/IP 的 HTTPS 兼容转发，待所有必要验证通过再更新 DNS。保留旧域名路径和外部回调契约。
7. 实查公网入口、身份链路与外部只读接口、前端静态资源、两台机器的独立探针、SLS 与监控；再触发迁移后数据库备份。真实手机登录、真实支付、真实生成是否执行必须单独说明。
8. 停用旧正式 unit 并加启动拦截，避免旧版发布脚本复活旧库。预发和其他应用留在旧机时，不能直接停旧 PostgreSQL 或退役整台 ECS。

### 恢复边界

新库尚未接收正式写入前，可以撤销维护窗口并恢复原入口。新库一旦有正式写入，就以新库为唯一权威：代码回退继续连接新库，ALB 切向另一健康新节点。不能只把 DNS 指回旧数据库服务，否则会丢失新数据。要回迁数据，必须重新设计反向同步与冻结窗口。

## 5. 迁移后的默认发布

军师具体命令与资源配置见 [集群部署](CLUSTER_DEPLOYMENT.md)。默认入口为 `bash scripts/deploy-prod.sh`：

1. 本机 devq 排队，获取跨聊天共用的远端发布锁；核对云实例、ALB 成员、主备权重、正式/测试配置及上一版本。
2. 固定 SHA，只构建已提交归档；备用机在未启用目录安装、编译、跑测试。两台使用相同的校验通过产物，不能各自拉取不同 HEAD。
3. 停止待更新实例的后台领单，等待 HTTP 在途和持久任务清空；超时保留旧进程，不提供强制跳过开关。未来持续高负载下应将 worker 独立部署，不靠长期等待全库任务变成 0 来支撑高频发布。
4. 更新备用实例，校验实际运行版本、配置、数据库、Tair、独立 ALB 探针；通过才给它正式流量。
5. 原主机权重变为 0，等待 ALB 排空时间与实际任务完成，再更新原主；主产品发布同时更新唯一 scheduler，等待定时任务队列收尾，备用 scheduler 只更新配置、保持停用。
6. 恢复 A=100、B=0，验证两边健康，写版本与追加发布历史，清理本次临时构建包，保留历史 release、配置和日志。
7. 任一步失败，优先把流量留给实际验证健康的节点；不能无条件切回 A，也不能把旧数据库作为恢复手段。修复后再按记录恢复发布。

schema 变化默认拦截；先做兼容的 expand/contract 迁移、备份及验证，再明确使用 `--schema-reviewed`。该开关只允许只读核对新 RDS 已具有目标结构，发布工具本身仍不执行 DDL、seed、reset 或 accept-data-loss。

## 6. 证书更新与常规维护

`bash scripts/renew-alb-certificate.sh --check` 只读查询。正常续签命令使用本机已登录 Alibaba CLI 与 Certbot 完成 DNS-01，距到期 35 天内签发新证书，核对既有 SAN、私钥匹配和有效期后上传到 CAS，更新 ALB 绑定并验证所有配置的 VIP/域名；失败自动恢复原绑定。DNS 清理只删除本次创建且内容仍匹配的挑战记录，不影响其他证书申请。

证书私钥与 ACME 账号位于本机 `.deploy-certs/`，目录 700、私钥受保护且被 Git 忽略。续签脚本不依赖旧 ECS、不复制云账号长期 AK；需要本机 CLI 授权仍有效。当前没有配置后台定时续签，须在维护节奏中运行检查/续签，不能把上传证书当作已托管自动续期。

旧机退役另开清单：解析/TTL/旧 IP 访问、预发、共享数据库、监控、证书和其他应用依赖全部解除后，再备份并逐项停止。不要因一个产品迁完就释放整机。

## 7. 每次归档的验收记录

至少保存：迁移范围、时间与操作人、源/目标版本和资源、备份 ID/校验和、数据核对结果、测试命令和退出码、实际部署 SHA/路径、ALB 权重与健康、外部依赖验证、SLS/监控证据、未执行的真实用户验收、切流后的恢复边界及遗留维护项。

本次军师迁移的历史验收包括 100/100 表行数和双指纹一致、真实 Chromium 99/99、支付幂等专项 26/26、入口 28 项；后续发布验证与证书续签记录另随本次上线工具交付记录更新。其他服务只能参考流程，不能复用这些验收结论。
