# 执行 tab 回归改造方案（2026-08-18 · v4.1，三轮 codex 评审收口）

> 背景：老板对 2026-08 IA 改版（问策/战局/锦囊/图籍/主公）不满意，要求回到更早参照的设计稿
> （619f105 那版：对话/战局/执行/智库/我的）的第三个 tab——**执行**。
> 两点明确反馈：① 锦囊独占 tab 太突兀，应该是「执行任务里搭配锦囊」；
> ② 执行页是用户粘性 / 上瘾机制的核心承载点，必须作为独立 tab 保留。
>
> 评审记录：v1 经 codex-cli review 结论「需修改」（三阻断项：产出误归因 / 老路由未闭环 / 合页拖慢高频页），
> v2 修订后复核仍余五条必改项（慢接口矛盾 / intent 契约 / 战果失败态 / 桥接判据 / 红点生产者），
> v3 全部收口，修订处标 ★。
> **v4（用户评审意见）**：① 「今日｜本周｜锦囊」三段维度不统一（时间×物件混排）——锦囊不再做段，
> 改「两段时间轴 + 锦囊三触点」，pouch 页整页保留降为普通页，修订处标 ★★；② tab 名新增「方略」候选并给出评估（§9）。
>
> 范围：weapp-native（小程序原生运行时）。PC 工作台的锦囊区、Taro 侧遗留 app.config.ts 不在本次范围，见 §9。

## 0. 一句话定案

**第三 tab 从「锦囊」换成「执行」（工作名，最终名待拍板，见 §9）：把现在挤在战局下半屏的
军令打卡机制整体搬出来独立成 tab，锦囊降级为执行页内的伴随内容——军令卡上配兵器、
当日新成品进「今日战果」、页底入口卡进锦囊页。**

新五 tab：**问策 ｜ 战局 ｜ 执行 ｜ 图籍 ｜ 主公**

不是简单回滚到 619f105：那版执行页（军令台）的机制内核（今日军令+打卡+回填+复盘）在 2026-08 改版时
被搬进了战局下半屏且一直在线上跑，本次是**把它搬回独立 tab 并升格**，同时保住 2026-08 改版里
验证过的正确决策（战局判断区、图籍、兵器条、七日打卡条、分发铁律）。

## 1. 为什么锦囊 tab 突兀（承认问题）

- 锦囊页回答的是「我做过什么」（检索 job），频率天然低——作品不会每天多一件，
  作为五分之一的一级入口，多数打开日它没有增量，占据 C 位却撑不起 C 位的访问频率。
- 「做一件事」的动机几乎总是从一条军令或一次对话里长出来的，而不是从翻作品架开始。
  把手艺格放在任务现场（兵器条）比放在独立货架上更接近用户的真实动线。
- 执行机制（打卡/回填/复盘/连续七日）才是日频行为，是留存的核心杠杆
  （见 [FABLE5]RETENTION_MECHANISMS.md），却被折叠在战局下半屏，
  滚过判断区才能看到，日活锚点没有一级入口。

## 2. 执行页设计（新 pages/execution，tab 第三位）

页头沿用 tab-header 规范：kicker「今天该做的都在这」· 大字「执行」· 背景表意字「行」。

### 2.1 两段 segment：今日 ｜ 本周（★★ 只留时间维度）

★★ v3 曾设计「今日｜本周｜锦囊」三段，评审指出维度不统一——前两个是时间轴，第三个是物件，
并列在一个 segment 控件里是分类错误。v4 定稿：**segment 只留今日｜本周**（纯执行节奏），
锦囊改为页内**三个触点**（见下），pouch 页整页保留、降为普通页。

**★ segment 控件 sticky 吸顶**；两段各自记忆滚动位置（至少保证切段回段首）。

**「今日」段**（从 pages/home 军令区整体平移，交互不改）：
- 今日军令列表：任务卡 + 完成打勾 + 长按删除 + 「让军师重排」。
- **兵器条保留原样**（order.weapon，服务端拆令时 1:1 配的工具）——这就是「执行任务里搭配锦囊」的
  第一形态：军令上直接写「军师配了兵器 · 海报快印…」，点「带我做」进对应军师对话或子应用。
- **★「今日战果」公共区（新增，不做任务级归因）**：当日新产出的成品以小缩略图
  横排在军令列表下方，「今天出的活」，点进详情、可「再来一张」。**不声称属于哪条军令**——
  评审确认 weapon.key 不是作品类型（ip/promo/shortvideo 均可能产报告或成片）、「同日」证明不了因果，
  端上启发式配对必然误挂，砸掉战果记录的可信度。真正的任务级回挂等阶段二链路做实（§5）。
  **★ v1 战果区只收海报一类**（creativePosters 是本地快接口）：成片的 videoWorks 是 12s 跨服务慢调用，
  不许被日频的今日段触发，成片进战果延后到「成片列表有快速聚合/服务端缓存」之后（可并入阶段二）；
  报告类当日只有 updatedAt 无新建判定，同样不进 v1。
  **★ 战果区读失败不整区消失**：出局部紧凑失败条 +「重试」，不阻塞军令核心区——
  整区不渲染会让「没有战果」和「读取失败」混成一样，违反本方案自己的空态铁律。
- **★ reviewDue 提醒条**：21:00 后复盘未做时，今日段顶部出一条紧凑提醒「今晚复盘还没做」，
  不能让红点把人带进来之后还要滚到页底找复盘入口。
- 富余兵器条（leftoverWeapons）、手动加军令、今日数据回填（线索/咨询/成交）、
  今晚复盘入口——全部原样平移。

**「本周」段**（平移 + 指标正名）：
- 连续七日条（实心/半实/空心/虚线四态）、按天分组军令记录、周空态引导。
- **★ 两个指标拆开叫**：七日条是「近七日执行」（军令完成态）；「连续复盘 N 天」是独立小指标
  （streak 来自复盘记录）。现状两者混在一个头部句子里，军令天天办完而复盘 streak 为 0 时
  会显得自相矛盾。统一大 streak 需要后端先定义「哪种行为算不断签」，本次不做前端混算。

**★★ 锦囊的三个触点**（回应老板「执行任务里搭配锦囊」，不再单设段）：
- ① **军令卡兵器条**（已有）：任务现场的手艺，「军师配了兵器 · 带我做」。
- ② **今日战果区**（本次新增，见上）：当日新成品横排在军令下方。
- ③ **页底常驻「锦囊」入口卡**：「出过的成品、会用的手艺，都收在锦囊里」→ 进 pages/pouch。
  **pouch 页业务内容整页保留**（摘 tab 身份、降为普通页，最近做的 + 手艺宫格逻辑不动）：
  分发铁律零迁移，老分享卡、旧「去锦囊」入口 **URL 不变**。
  ★★ 但「整页一字不动」不成立，页面壳必须随身份改：①补返回按钮，无返回栈时兜底
  switchTab 到执行页（执行是 tabBar 页，不能用 redirectTo；防孤立子页）；②去掉 tab 专属 UI——syncTabBar 调用、底栏渐隐留白、
  coach-marks 组件（引导箭头会指向已不存在的 tab 位）；③四路聚合的 90s 缓存现挂在页面实例上，
  降普通页后退出再进会新建实例、videoWorks 重打——缓存要**提升到模块级**（services 层）。
  迁移期入口卡挂一次性小提示「锦囊搬到这了」，打开过即消失。

### 2.2 ★ 加载架构：三个独立状态机，不许合并成一个 load()

执行页是日频高频页，锦囊四路接口（agents/posters/videoWorks/reports，其中 videoWorks 跨服务、
超时 12s）不许挂在 onShow 上无条件全发：

- 今日/本周共享 `executionCoreState`：只加载军令/回填/复盘等执行数据。
- ★★ 执行页在核心数据之外只多**海报一路**（今日战果）；锦囊四路接口留在 pouch 页里
  按原样惰性加载——**执行页任何情况下不得调用 videoWorks()**，守护断言照写。
- **★ 战果区与 pouch 页共享同一 works 缓存层（统一 TTL + single-flight）**：执行页取过海报、
  再进锦囊页不许对同一接口重复并发；反之亦然。
- 复盘抽屉数据（decisions/reminders/经营模板）在打开抽屉时独立加载。
- 每组独立 loading/error/ready，不共用一个 loading 布尔；失败不许伪装成空数组
  （home 现存的几处静默降级搬家时顺便拆清，weapp-empty-vs-failed-state 铁律）。

★★ 文件组织随之简化：execution 页 = home 军令区平移 + 战果区 + 锦囊入口卡，单页即可，
不再需要 pouch-view 搬迁；体量仍大就按视图拆文件，但不背锦囊逻辑。

### 2.3 角标与游客态

- tab 角标：reviewDue 红点改挂执行 tab（index 2）。**★ 两处渲染 + 一处生产都要改**：
  custom-tab-bar 的红点索引现在是硬编码；问策终态「合体浮岛」那排自绘 tab 现在只显示 unread、
  没有 reviewDue——两套底栏必须同步。**★ 生产者补齐**：`store.loadReviewBadge()` 现在只有战局 onShow
  在调，战局不再是必经页后要挪进公共 tab 生命周期（page.js 基座或 sessions onShow 兜底），
  验收标准「21:00 后冷启动直接落在问策页，执行 tab 红点也要亮」。问策 unread 角标不动。
- 游客态：整页一屏引导（复用 pouch 游客态口径——不取数、不摆「—」），
  文案「军令、打卡和锦囊都记在你的名下 · 登录后开始」；登录门不前置、可取消。
- 四态逐个核：加载中骨架 / 读失败重试条 / 真空态引导 / 有数据，两段与战果区分别判。

## 3. 战局页瘦身（判断纯化）

军令区搬走后，战局回归纯判断面：今日献策、军师判断 hero、三势、天时条、「现在不能做」风险卡、判断依据。

**★ 桥接条做三态**（评审 P0：不能只留一个无状态 N/M，否则「看见判断→认可→形成军令」的转化口断了）。
**判据优先级写死：今日有军令 → 有有效判断 → 无有效判断**（「有案卷但判断为空」按第三态处理，
不许因为案卷存在就亮出令 CTA）；核心数据读失败时桥接条只出「重试」，不出任何业务 CTA——
读失败误判成「无案卷」会把老用户当新用户导流：
- 今日有军令：「今日军令 2/3 · 去执行」→ switchTab（走 gotoExecution('today')）。
- 有有效判断、今日未出令：「就按这个判断来 · 出今日军令」→ **在战局直接触发 commitBattle**
  （它带幂等/套餐到期/额度不足处理，整段逻辑留一份、战局与执行页共用 service），成功后自动切到执行。
- 无有效判断/无案卷：「先和军师定方案」→ 进对话。

## 4. 锦囊 tab 退位的迁移清单

- **★★ pages/pouch 保留业务内容、摘 tab 身份**（不做 stub、不搬内容）。兼容口径修正：
  **URL 不变，导航 API 必须迁**——wx.switchTab 只能开 tabBar 页，现存三处 switchTab 到 pouch
  （work/poster、work/gallery、work/command topics）降级后会直接失败，全部改 navTo；
  页面壳改造见 §2.1 触点③。守护测试加「全仓不得 switchTab 到 pouch」。
- **★ pages/studio stub 本批次保留**（服务端订阅消息 wechatSubscribe 默认落地页仍是
  pages/studio/index，历史已发送消息、旧分享卡存的是旧路径）：studio stub → switchTab 执行；
  删除条件「服务端默认落地页已改 + 有路径访问数据或明确兼容期限」。
- **★ segment intent 机制（范围缩小到 today/week）**：统一 nav helper `gotoExecution(segment)`，
  写一次性内存 intent（不落 storage）再 switchTab；execution onShow 消费后立即清除，
  switchTab 失败/超时同样清除。调用方：studio stub、战局桥接条、coach-marks（它现在是直接
  wx.switchTab，要接入）、custom-tab-bar 与问策浮岛。**显式点击执行 tab 才设 today**；
  从详情页返回（无新 intent）时保留原 segment 与滚动位置，onShow 不许重置。
- coach marks（services/coach.js STEPS）升 v3：战局步文案改「上半是判断，做事去执行」；
  ★★ 原锦囊步与执行步**合并为一步**（route `/pages/execution/index`，文案「军令在这打卡；
  军师配的兵器、出过的成品从页底锦囊进」），STEPS 数量减一。
  **★ legacy 键位前缀 v1→v2 同步升**，保证已完成 v2 的老用户会补看一次 v3。
- 主公页「已启用的兵器」（账单视角）不动；图籍不动。
- 底栏图标：执行 tab 复用 muster（打勾名册，语义「点检待办」贴切）；
  brocade（束口袋）字形留给 pouch 页页头与执行页锦囊入口卡。

## 5. 「军令 × 产出」任务级回挂 = 阶段二（动服务端，单独评审）

v1 只做不归因的「今日战果」公共区（§2.1）。任务级回挂必须链路做实才上：

- 兵器「带我做」deep-link 带 orderId → 对话/需求单/视频 project 透传 →
  海报 CreativeJob、成片（AIStar 跨服务）、报告 ReportDoc/ReportVersion 各自落 orderId
  → 军令接口回吐 works[]，端上把成品挂回军令卡。
- **★ 评审补充的实做清单**：shared/contracts.d.ts 定 orderId/works 契约；orderId 归属用户/租户校验
  （禁止客户端任意关联别人的军令）；跨服务失败/重试/历史版本归属；一件作品可否对应多条军令的规则。
- 上了任务级回挂后，「今日战果」区继续收没有归因的散活，两者并存。

## 6. 不动的铁律（改版红线，全部继承）

- 分发铁律「第一次归军师，第二次起归锦囊」：手艺格置灰导览、不标价、教育归军师——全部原样。
- 文案铁律说人话：tab 名不造新黑话（「执行」为工作名，最终名 §9 待拍板，四候选都是现成词）。
  复出动词按类型（再来一张/再出一条/改一版）不动。
- 对外价格数据归运营，端上零写死类别，动态 agents 长格机制不动。
- 空态 vs 读失败不许混；游客可浏览、登录门可取消。

## 8. 风险与回滚

- ~~待拍板 ①~~ **已定名「今日」（ac5155f 落地）**：页头「今日/今」，段名按候选规则改「今天/近七日」，
  工程路由保持 pages/execution 与 gotoExecution 不变。以下候选评估留档：
  - **军令（推荐）**：产品已经每天在教用户这个词（今日军令），页内主体就是它；动作感最强，
    与其余四 tab 的军事语域一致。角标红点、复盘提醒都长在军令语境上，自洽。
  - **执行**：老板原词、可读性最高；缺点是现代白话，与其余四 tab 的军事语域有落差。
  - **方略**：语域对，但语义偏「谋」不偏「行」——仓库里「方略」现主要用作战略报告标题；
    找「今天该干嘛」的人不会点它，找方案的人点进来看到的却是打卡条，和战局/方案库双向撞车。不推荐。
  - **点兵**：语义其实通（5c1f705 时代的点兵页主体就是军令打卡回填复盘），但这个名字上一轮
    IA 里刚被合并撤下，三周内复用会加重「改来改去」的观感；且「点检兵力」终究隔一层，弱于军令直白。
  - **今日**（第二轮补充候选）：三候选（功课/落地/今日）里最优——tab 名直接编码「每天来一趟」，
    与上瘾机制同构，红点语义自洽（App Store/健身类 Today tab 先例）；代价：只说「何时」不说「何事」，
    且与页内「今日｜本周」段撞名，选它则段名改「今天｜近七日」。
  - **落地**：语义最准（老板自己说「方案落地」的词），战局→落地动线顺；动词性强、现代商务语，
    语域落差与「执行」同级。
  - **功课**：有日课感但身份关系反了——用户是主公，军师不能给主公留功课，军事叙事被拆；不建议。
