自绘导航条的额外好处
微信官方的 custom-tab-bar 只在 tabBar 页渲染，二级页面天生没有导航。 但方案乙的导航条是我们自己的组件，所以对话页也能挂 —— 桌面上从 tab 进到对话， 左边那条不会突然消失。

范围要划死：只给五个 tab + 这一个对话页挂。 packages/work 里另外二十多个二级页（方案库、命盘、账本…）保持「全宽 + 返回」， 它们本来就是进去办一件事就出来。
不给对话页加副栏。这一页只有一件事：说话。 右边硬塞「引用的资料 / 本次方案」会把注意力从对话里拽走，而且那些内容在图籍和锦囊里各有正主。

降级必须是「同一棵 DOM 换排布」，不是「另写一套」
问策那一版已经验证了这条路：常驻侧栏和半屏抽屉是同一棵 WXML、同一份数据， 只有 CSS 和一个布尔量不同。剩下四个 tab 也照这个来 —— 副栏是一个 <view class="aside"> 包住原有的那几块， 窄档下它只是个透明容器，宽档下才移到右侧成栏。

正因为是 wrapper，副栏只能收「在手机上本来就相邻」的块。 包一层就意味着这几块在手机上只能出现在一个位置 —— 所以战局的天时（手机上排在三势之后） 和图籍的主 CTA（排在页尾）都不进副栏，否则窄屏会被动改版。 四个 tab 的副栏都是按这条挑出来的，手机版一个节点都不动。
窗口拖动时 Page.onResize 会连续触发， 档位切换要幂等（问策的 syncRail 已经是「值没变就直接 return」）， 否则拖一次窗口会打出上百次 setData。
