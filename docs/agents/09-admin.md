## 9. 运营后台（admin）

### 9.0 信息架构与外壳（2026-07-28 运营视角改版）

改版动机是「22 个目的地平铺在一条 56px 宽横滚底栏里、桌面端整屏当手机用、请求失败伪装成没数据」。现在的结构：

- **`admin/src/nav.ts` 是导航 SSOT**：29 个 section 按**「只读的归观测、可写的归配置」**归入 8 个运营场景组——`today 今日`（概览）、`people 用户`、`revenue 经营`（订单/漏斗/钻石消耗/Token 成本，4 项全只读）、`growth 增长`（**邀请关系**/**邀请链**/**代理分销**/邀请增长；2026-09-02 新增，只读的「邀请增长」由 `revenue` 搬入，key 与已分享的 `#/referral` 链接不变）、`studio 智能体`（顾问/技能库/知识库/检索调试）、`observe 观测`（**会话工作台**/调用诊断/内容审核/审计日志）、`catalog 商品`（套餐/单次付费/生态工具）、`settings 配置`（模型配置/功能开关/创作任务/行业基准/献策/**问策入口**/问卷/运营账户——已满 8 项，再加就拆组）。「问策入口」页（2026-08-08 WP5）承载提示问题池 / 进场主动消息池（含 chips 编辑）与改版灰度权重（chat 占比单滑杆 + 急停说明；权重展示归一化到 100%，与服务端 `effectiveArms` 同源）。label、hint、icon、`ownerOnly`、命令面板别名都在这里，页面不再各写一份标题。**分组时看页面的主导动词，别看次要属性**——初版把「模型配置」放进「稳定性」（理由是端点池冷却算健康信号），但该页主体是写操作，一个写屏混在三个只读观测屏里正是运营找不到东西的根因；同期「配置」组堆到 8 项混装商品/开关/内容/权限，也一并按此原则拆开。新增分区要么进现有组，要么拆组，**单组不超过 8 项**。
- **外壳 `admin/src/App.tsx` 只做**：鉴权、分组导航（桌面左栏 204px / 移动底栏按组 flex 均分，组数有界=永不横滚；组名保持 2-3 字）、分区 segmented、hash 路由、详情面板挂载、命令面板、toast、改密弹层。业务视图全在 `admin/src/views/{overview,users,revenue,studio,observe,sessions,catalog,settings,model}.tsx`（原 2841 行 App.tsx 已拆分，文件名对齐组名；`model.tsx` 与 `sessions.tsx` 因页面体量/实体链路单独成文件，逻辑上分别属 `settings` / `observe` 组），共享格式化在 `format.tsx`，共享组件在 `components.tsx`。
- **`admin/src/router.ts`（极简 hash 路由，零依赖）**：`#/<section>[/<id>][?params]`。刷新 / 浏览器返回 / 把链接甩给同事都能回到同一现场（含打开着的用户详情，如 `#/users/<userId>`）；非法或越权 hash 兜回 `#/home` 而不是白屏。旧版当前 tab 与详情态只在 React state 里，F5 就丢现场。
- **命令面板 ⌘K / Ctrl+K（`CommandPalette.tsx`）**：按名称/别名跳任意一屏，或按姓名/手机号直接定位用户（纯数字输入优先匹配用户）。新增目的地必须能在这里被搜到。
- **`admin/src/useResource.ts` + `components.tsx` 的 `ViewState`**：统一 loading（骨架屏）/ error（带服务端原文 + 重试）/ empty 三态，并在 `PageHead` 显示数据新鲜度。替掉旧版散落 32 处的 `.catch(() => {})`——接口 500 时页面渲染成「近 30 天暂无订单」，运营会把它当业务结论上报。**React 18 StrictMode 约束（2026-09-02）**：取数有效性必须由每一轮 effect 自己的 `cancelled` cleanup 管理，不能用组件级 `alive` ref 只在卸载时置 `false`；StrictMode 的 mount → cleanup → mount 会把后者永久烧死，开发环境所有后台页都会卡在骨架屏。跨请求只接受最后一次响应仍由递增 `reqId` 负责；回归见 `admin/src/useResource.test.ts`。
- **交互完整性（2026-08-17）**：共享 `Switch` 统一开关的键盘/读屏语义；`useDialogFocus` 统一弹层首次聚焦、Tab 圈定、Escape、关闭焦点归还与长内容视口内滚动。登录状态探测、账号/密钥提交、命令面板找人、技能目录和已学记忆治理均将网络失败与真空结果分开，并给出原文/重试；账户菜单改为同级 trigger + `role=menu`，toast 用 `role=status`。主动作白字统一落 `--accent-deep`，次级说明灰提升到可读对比度；`lint:ui` 额外阻断 `:root` 外 hex、字面量 z-index、`div.sw` 和空 catch。
- **`admin/src/api.ts` 的 401 / 403 分流（2026-07-29 修，回归用例 `admin/src/api.auth.test.ts`）**：**401 才是掉线**——清 token + 广播 `admin:unauth` 切回登录页；**403 是权限不足**——保留登录态，抛 `{ code, status: 403 }` 由页面就地提示（服务端原文优先，缺文案时按 `OWNER_ONLY` / `ADMIN_AGENT_FORBIDDEN` / `ADMIN_FORBIDDEN` 兜底人话）。`useResource` 把 403 记进 `Resource.forbidden`，`ErrorState forbidden` 换成「没有查看这块内容的权限 · 找 owner 授权」并撤掉重试按钮（再点还是 403）。**新增 requireSuper 交互时的两条要求**：① 入口按 `isSuper` 收起并写明只读（别摆注定失败的按钮）；② 写操作的 `catch` 必须透出 `e.message`，禁止盖成固定文案——`catch { toast('保存失败') }` 会把「需要 owner 权限」说成故障，让运营去查网络或反复改参数。旧写法是 `401 || 403` 一起踢登出，等于把权限问题伪装成掉线，且重新登录必然重现。
- **今日「待处理」队列**：卡单（已支付未发放=资损单）、近 24h 调用失败、端点冷却、审核拦截、额度耗尽五格，全部复用既有接口（`payments.stuck` / `traces` / `aiRouting` / `moderationLogs` / `users`），点进去就是筛好的清单；各格独立取数，一个接口挂了只该格显示「—」。全零才折叠成一行「无待处理」。
- **资金/破坏性动作统一 `ConfirmDialog`**：回显「对谁/多少钱/哪一单」，退款与关闭合规开关要求手打确认词，退款原因在弹层内收集并入审计。旧版退款原因是 `window.prompt` 收的、回车即执行、不显示金额。
- **跨屏直达**：订单 →「查用户」（订单契约只有 `userName`，故按姓名带进用户搜索 `#/users?q=…`；补 `userId` 需改后端契约，留作后续）、审核拦截 →「查看用户」、Token Top 用户 → 用户详情。
- **智能体上架与用户端目录一致性**：新增/详情都必须明确 `Agent.type` 对应的「用户端入口」；`advisory/custom` 动态进入小程序「对话 → 专业参谋」，`creative` 动态进入「执行 → 内容出品」，两页显示时重拉 `/agents`。后台 `enabled=true` 即进入对应目录，不得在 app 再维护一份 key 白名单。
- **技能/知识可钻取且知识按用户辨识**：技能库内置项可点开查看中文名、执行类型、说明与只读参数 Schema；知识库每行必须带 `userId/姓名/手机号/租户`，支持按用户筛选并点开正文与切片。`/admin/users/:id/knowledge/:kid` 的详情/删除/重嵌必须同时校验 `KnowledgeItem.userId=:id`，不能只按同租户放行。
- **观测信息人话化与审计降噪**：调用诊断用 `LlmTrace.userId/tenantId/sessionId/agentKey` 回填来源用户、手机号、租户与智能体中文名；`model/endpointId/endpointLabel` 保存实际命中的模型及端点快照，端点改名或退出池后历史记录仍可辨认。界面主信息显示「对话回复/方案生成」等业务标签与实际端点，`general/deliverable/ip` 原始 key 只留排障标识。`/api/metrics` 是 Prometheus 机器抓取，不写 `AuditLog`；修复前历史抓取默认过滤，只有显式 `includeMetrics=true`/「含监控抓取」才展示，避免淹没用户行为。**2026-08-20 完整性重构**：`GET /admin/sessions` + `GET /admin/sessions/:id` 提供跨用户会话检索、消息游标、生成任务与 trace 下钻；`GET /admin/audit-view` 提供服务端日期/状态/关键词筛选与精确分页，并正式返回 `requestId/sessionId/operator` 供“同一请求链 → 关联会话/用户”跳转。`services/adminRange.ts` 是概览、Token、trace、会话和审计的统一时间解析器，自定义日期按北京时间自然日、最长 3660 天；概览比较所选区间与前一等长区间，不再同屏混用固定 7/30 天。**滚动预设的 `toExclusive` 必须略过当前时刻（当前为 60 秒）**，否则数据库 `now()` 与 Node 同毫秒新建的 trace / 审计会被严格 `lt` 上界排掉；对外 `view` 仍截至真实现在、天数不含余量。自定义日期上界不加余量，避免运营选「截至昨天」却查进今天；无显式上界的 trace 查询不应凭空添加 `lt now`。详细审计见 `docs/ADMIN_CONSOLE_REFACTOR_2026-08-20.md`。

页面/接口：概览看板、**注册用户管理**（小程序注册用户、微信绑定、租户/套餐、最后会话、会话/成果数、算力余额，并可点进用户详情为其开通/取消 `unlock` 智能体）、**会话工作台**（跨用户搜索、消息/生成/trace 同屏下钻）、**算力消耗**（按用户汇总赠送/消耗/余额、30 天活跃、成果数）、**审计日志**（服务端日期/关键词/状态筛选与分页；默认过滤 `admin.*` 和 metrics 噪声；单行展示用户 API、登录尝试、业务动作、用户/租户、摘要、方法/路径/状态码、IP/UA，详情展示 request/session/operator 与原始 payload；`adminAuditView.ts` 的原生 SQL 时间边界必须经 `utcTimestamp` 与 Prisma 的 UTC naive `DateTime` 对齐，禁止裸绑 `Date`，否则北京时间当天会漏日志）、每日献策库（增删改启停）、智能体/功能配置（新增智能体、基础信息、`free/unlock/metered` 定价、System 提示词、对外问候语、专属理解提示 `memText/learnText` + Agent Memory 策略 + **上架/下架**，前台 `/agents` 默认只展示已上架功能）、**技能库**（新增/编辑自定义 HTTP 工具，复用后台统一组件语汇）、**模型配置（凭证 / 接入点 / 六用途路由，含直测、深度探活、分流池与用途预算，即时生效）**、建档问卷、套餐编辑。所有 `/api/admin/*` 路由由 `services/adminAuth.ts` 保护；入口 `admin/src/App.tsx` + `admin/src/views/*` + `AgentDetailPanel.tsx`，API `admin/src/api.ts`（类型来自 SSOT）。智能体详情保存采用真正的 dirty-field PATCH，后端继续统一审计并重算 `draftDirty`；数据库草稿/已发布版本才是运行时事实来源。Agent Memory 开关保存到 `Agent.memoryConfig` 并由后端真实读取；`LlmTrace.contextJson` 保留可排障但不含记忆正文的上下文快照。开发期 Vite 代理 `/api → localhost:4000`。后台全屏无边框，桌面左栏 + 移动 8 组底栏（flex 均分、永不横滚；375px / 8 ≈ 46px 一格，故组名保持 2-3 字）+ 组内 segmented；样式必须保持视口安全收缩、横向隐藏、长文本断行、键盘可达与弹层焦点完整。

- **「增长」组与 shadcn 模块（2026-09-02）**：新开第 8 组 `growth 增长`，四个分区 `invites 邀请关系` / `chain 邀请链` / `distribution 代理分销` / `referral 邀请增长`。为什么另立一组而不塞进「经营」：本轮补的是邀请体系的**运营面**（查关系账本、看一个人的上下游链路、登记代理与结算佣金），三页里两页带写操作，按「主导动词决定归属」既不属只读的「经营」也不属平台级的「配置」；只读的「邀请增长」一并搬进来，运营查邀请的动线本来就该收在一处（搬完 `revenue` 回到 4 项，两组都在「单组不超过 8 项」内）。路由 `#/invites`、`#/chain[/<userId>]`、`#/distribution[/<distributorId>]`——**`chain` 的 `route.id` 是 userId，`distribution` 的是 distributorId，别混**。跨屏直达：邀请关系行内「被邀人链 / 邀请人链」、用户详情面板「查邀请链」、代理名册「查邀请链」、邀请链上的「代理档案」。写操作只有补绑（`invites`）与代理/规则/结算（`distribution`），全部 `isSuper` 才渲染入口 + `catch` 透出 `e.message`；总开关与冻结期只显示并链到 `#/flags`（一个数字只有一个写口）。
- **shadcn 模块（只进「增长」组）**：这三页是仓里**唯一**用 Tailwind v4 + shadcn/Radix 的地方，边界是目录——`admin/src/growth/**`、`admin/src/components/ui/**`、`admin/src/lib/**`。**旧页面一行没改，也不许 import `@/components/ui`**；新模块不许用 admin.css 的组件类（`PageHead` 输出的旧类除外——admin.css 无作用域，页头因此全站一致）。四条不许回退的约束：① **不引 preflight**（会重置旧页面的 `button`/`h1..h6`/`table`/`input`），缺的三样自己补——`.sc` 的底色文字、`.sc *` 的 `border-color`、Radix 浮层用 `container` prop 挂进 `.sc` 内的挂载点（`src/lib/scPortal.tsx`）；② `utilities.css` 用 `source(none)` + `@source` 只扫那三个目录，**白名单不许放宽到 `admin/src`**（旧页面里的 `block`/`full`/`on`/`fixed` 与工具类同名，扫进去会按 layer 顺序盖掉旧样式）；③ shadcn 变量一律 `--sc-` 前缀（admin.css 的 `--accent` 是品牌金，shadcn 的 `--accent` 是悬停底，同名互相污染），色板全部映射到既有纸/墨/金 token，**One Command Color 不变**；④ **不做暗色模式**——Tailwind v4 的 `dark:` 默认等于 `prefers-color-scheme: dark`，`shadcn.css` 用 `@custom-variant dark` 把它重定义成永不命中的选择器（别手删组件里的 `dark:`，下次 `shadcn add` 会覆盖回来）。`scripts/audit-admin-ui.mjs` 只加一条豁免：那三个目录**跳过规则 1**（class 必须在 admin.css 里定义），inline 硬编码颜色 / 控件一次性 inline style / `div.sw` / 空 catch 照旧阻断；admin.css 一行未改。逻辑层两边共用（`useResource` / `PageHead` / `router` / `api.ts`），三态与空态在 `src/growth/ui.tsx` 有一套 shadcn 皮肤但**语义与 `ViewState` 完全一致**（loading/error/empty 不许互相冒充、error 带服务端原文 + 重试、403 不给重试按钮）。归因结果 / 来源 / 短 id / 人物标签的人话表抽到 `src/growth/labels.ts`，`views/referral.tsx` 改成 import 同一份（两屏对同一个 `outcome` 说两种话，运营会当成两件事）。映射表与禁令全文见 `admin/DESIGN.md`「§7 shadcn 模块（增长组）」。

### 9.1 邀请增长（2026-08-18，P3；`admin/src/views/referral.tsx` + `server/src/routes/adminReferral.ts`）

「经营 · 邀请增长」一页四个 tab，**一份数据三个投影 + 一个留位**，全只读。端点四个：
`GET /admin/referral/{overview,tree,risk,tenants}`——`tenants` 单独一个是为了让「租户筛选项没加载出来」
能显示成可重试的错误，而不是伪装成「暂无带邀请关系的租户」（业务空态与读失败不许混）。
四个 tab **各自持有取数、切到哪个才挂载**：只看一张静态 UML 说明图不该触发树聚合与风控扫描。

- **视图选型有理由，不是审美**：① 本体 Schema 用 **UML 类图**（看字段与基数），**刻意不用力导向图**——实例一多就是毛球，且每次刷新布局都不一样、没有阅读逻辑；② 邀请关系树用**从左到右的层级树**（邀请关系天然有方向与层级），节点大小=直邀人数、底色=开通状态、红环=风控标记，点节点展开/折叠；③ 风控用 **IP ↔ 新号二部图**——正常用户分散在各自 IP、刷号聚集成一个 IP 连一串新号的扇形，这个形状要一眼可见；**响应不下发 `userAgent`**（前端一处不展示，把 IP + 用户 id + 手机号 + 设备指纹一起端给所有后台账号是没必要的隐私扩散），手机号一律走 `services/audit.ts` 的 `maskAuditPhone` 掩码（树节点同理——树上挂着风控红环，与风控屏属同一关联面）；④ **转化漏斗留位未做**，卡在 `ClientEvent` 没有聚合读端点（§13 ③），不是卡在画图。
- **零图表依赖**：`admin` 的 dependencies 只有 react/react-dom，三张图全是手写 SVG。**颜色一律在 `admin.css` 的 `.rf-*` 组件类里用 token 定义，`.tsx` 里只算几何**（x/y/r/width）——这是 `lint:ui` 的硬约束，也让三张图的配色只有一处可改。树的布局是**每个可见节点占一行 + 直角折线**：可预测（同一份数据每次打开完全一样）、展开只在下面插入行，且**天然不会重叠**（同一行不会有两个节点）；最后一列右侧必须留够标签宽度（`T_TAIL`），否则 L3 的元信息会被 viewBox 直接裁掉。宽图一律裹在 `.rf-scroll` 里自己横滚，页面主体永不横滚。
- **端点单独成文件**：`routes/adminReferral.ts` 自挂同一把 `requireAdmin`（admin.ts 已 2900+ 行，三个投影各要一次成形）。树接口用**物化路径一条 `OR`（lv1/lv2/lv3 各有索引）取全三级子树**，配合一次 `groupBy(lv1)` 拿到任意深度都准的直邀数 + 一次 `findMany` 补名字/套餐，**没有逐层展开的 N+1**；根 = 直邀最多的前 N 人（投影不是全景，排序稳定可预测）。风控接口把聚集判定**整体下推到 SQL**：一条 `GROUP BY clientIp HAVING COUNT(DISTINCT newUserId) >= 阈值` 直接出组（并在同一条里带出 `group_total`），名单用 `DISTINCT ON (clientIp,newUserId)` 取每人最早那条、再 `ROW_NUMBER() OVER (PARTITION BY clientIp)` **按组**限量。**行级上限已彻底删除**——初版是「先全局 `take: 5000` 再在内存里去重判阈值」，那会让某个 IP 的 5000 条重复旧留痕把另一个真实聚集组整组挤没、页面显示「没有聚集」（2026-08-18 复核判为阻断：风控视图唯一的价值就是看见聚集，这种漏报比没有这块屏更糟）。截断只发生在组数上且**如实透出 `groupTotal`**；`scannedIps` / `scannedAttributions` 由一行 `COUNT(DISTINCT clientIp), COUNT(*)` 给出，让**「扫了 200 个 IP 没有聚集」与「一条数据都没有」在界面上分得开**。树的红环调**同一个** `riskGroups()`（同窗口、同阈值、同组数上限）解析，所以红环集合恒等于风控屏本次返回的组——否则会出现「树上标红、风控屏里找不到那个 IP」。
- **阈值归运营，不写死**：聚集阈值是功能开关 `referral-risk` 的 `payload.ipMin`（默认 5，区间 2~200），区间与默认值由 `routes/adminReferral.ts` 导出、`FEATURE_FLAG_CATALOG` 引用，两处不会漂移。**刻意另立一个 flag id 而不是复用 `referral`**：`PATCH /admin/flags/:id` 的 number 分支是整块 payload 覆盖写，两个数值挤一个 flag 会互相抹掉。读阈值走 `featureFlagPayload(..., { fresh: true })`，运营改完当场能验证；**读失败照抛 5xx，绝不用兜底默认值算出一份看着正常的名单**。
- **口径同源**：「已开通付费」复用 `planGate` 的判定（`planId` 存在且 `isExpired(planExpiresAt, now())` 为假，时钟走 `clock.now()`），与「我的邀请」的 `activatedCount`、与套餐页是同一个答案；树上的风控标记与二部图**同一批超阈值 IP 组**，两屏不会各说一套。**公理 5「风控预警不阻断」**：这一页没有任何封禁/拉黑/停发奖写操作，端点也只有 GET。
