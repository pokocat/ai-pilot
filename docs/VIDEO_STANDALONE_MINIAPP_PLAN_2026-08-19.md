# AI 短视频独立小程序 · 产品与工程规划

> 状态：定稿 v1（2026-08-19）。初稿由 Fable 起草，经一轮独立对抗评审修订；codex 因配额受限未参与本轮（用户拍板跳过）。
> 背景：把现有「快拍」子应用从军师小程序中抽出，升级为独立的 AI 短视频生成小程序。
> 关联事实文档：`docs/VIDEO_SUBAPP_PLAN_2026-08-10.md`（分包形态现状）、`docs/DEPLOYMENT.md` §8.1（环境拓扑）、AIStar 仓 `docs/clip-avatar-video-plan.md`（生成底座）。

---

## 0. 一句话定位

**一个「数字资产驱动」的 AI 短视频工厂**：用户把自己/企业的数字资产（数字人形象、克隆声音、真人素材、品牌视觉）存进来，用模板批量生产带真实感的短视频。

差异化不在「能生成视频」（所有大模型套壳都能），而在三件事：

1. **资产一致性**——生成出来的视频里是「你这个人、你的声音」，人脸与声音的一致性今天技术上可兑现；场景与产品的一致性按分级策略诚实兑现（见 §4.3，不过度承诺）；
2. **模板化生产效率**——实体店主和企业不需要创作自由度，需要「今天再出三条」；
3. **闭环链路**——从想法到成片到复用（Remix / 变体），不是一次性生成工具。

## 1. 用户分层与节奏

| 用户 | 典型场景 | 关键诉求 | 进入节奏 |
|---|---|---|---|
| 实体店主 / 个人创作者 | 数字人口播、门店引流、倡导类模板片 | 不会剪辑、要快、要像自己 | **M1 唯一目标用户**，单账号 |
| 代运营 / MCN | 替多个商家批量出片 | 多主体素材管理、批量 | M2 起，用「单账号多主体资产分组」轻方案顶住，不建组织体系 |
| 企业（老板/市场部） | 企业宣传、产品介绍、带货素材 | 品牌一致性、发票合同 | 拿到第一个企业合同再上 Org/成员/审计（评审结论：冷启动同时伺候三层是伪命题） |

**M1 硬约束：零资产新用户也要 10 分钟拿到成片。** 克隆训练是小时级，新用户第一条片必然用**公共数字人库**（平台预置形象+声音）+ 模板出片——公共数字人库是 M1 必备项，不是可选项。

## 2. 核心对象模型

```
Asset 数字资产 ──引用──▶ Template 模板 ──实例化──▶ Project 项目(草稿)
                                                     │ 提交
                                                     ▼
Work 作品 ◀──产出── Job 生成任务(异步,分镜 DAG,可取消)
  │ Remix / 一键 N 变体（逆向链路回到 Project）
  └─ 溯源快照：模板版本+提示词+资产引用+供应商+参数
```

### 2.1 Asset：数字资产的三层本质

资产不是「文件」，是三样东西的组合：

- **一致性锚**：让下游生成保持「同一个人/同一家店」的材料——参考图集、供应商侧训练引用（avatarId/speakerId）；
- **权利凭证**：谁的脸、谁授权的、能用在哪——授权快照、本人声明、可删除承诺；
- **可调用引用**：生成时直接消费的 ref，不是下载的文件。

**关键字段 `vendorAffinity`**：数字人形象和克隆声音是**绑定训练方的有状态资产**——石榴训练出的 avatarRef 拿不去火山口播。资产模型必须记录训练供应商，路由与故障转移按此约束（见 §4.2）。

### 2.2 资产类型体系

| 大类 | 类型 | 存储形态 | 生命周期 |
|---|---|---|---|
| **身份类**（有状态，带 vendorAffinity） | 数字人形象 | 源视频/照片 + 供应商 avatarRef + 预览图 + 参考图集 | 采集→训练中→就绪→失效/删除（连带删供应商侧） |
| | 克隆声音 | 声音采样 + 供应商 speakerRef + 试听样本 | 同上 |
| **素材类**（无状态） | 真人出镜素材、实拍 b-roll、图片、BGM | OSS key + 缩略图 + ffprobe 元数据 | 上传→机审→可用 |
| **品牌类（企业，M2）** | 品牌包 BrandKit（logo、VI 色、slogan、片头片尾）；场地/产品参考图集 | 配置态 + 打标图集 | 上传→**分级**（非拒收）→可用 |
| **衍生类** | AI 生成片段 | 生成中间产物 | **系统默认留存 7 天 + 推荐收藏**（不指望用户主动收藏），收藏才转永久 |

要点（吸收评审意见后的修正）：

- **企业照片按真实行为设计**：店主只有手机随手拍，没有「摄影师标准照」。质量门从「提交前拒收」改为**分级**：可做首帧 / 只能做 b-roll / 建议重拍；配「拍摄引导相机页」（构图框+要点提示）帮用户拍出可用素材。AI 自动打标（门头/车间/产品特写）必须可人工修改。
- **权利层**：身份类资产强制本人/授权声明 + 快照留存；删除资产连带删除供应商侧训练引用；素材过机审再入库。
- **存储生命周期**（成本护栏）：中间产物 7 天清理；免费用户容量上限；付费存储扩容沿用既有 `video_storage_pack` 模式。

### 2.3 Template：模板 = 脚本骨架 + 分镜编排 + 资产槽位

```
Template
├─ 分类：数字人口播 / 直播带货 / 企业宣传 / 倡导纪实 / 产品种草 …
├─ scriptSkeleton：分段文案骨架 + 变量（店名/行业/卖点），可 AI 改写
├─ storyboard：每镜的生成方式声明
│    shot.kind = avatar_talk   数字人口播（音频驱动口型）
│              | gen_video     AI 生成（声明参考注入等级，见 §4.3）
│              | user_footage  用户实拍素材填充（产品特写只允许此类）
│              | fixed_clip    模板固定片段（片头/片尾）
├─ assetSlots：资产槽位（类型约束 + 按标签自动推荐）
└─ 版本化：published 版本不可变，项目锁定模板版本
```

**模板内容供给是隐藏的最大工程之一**（评审指出，原稿零排期）：现有底座的模板服务只是片尾管理级别；一个能打的模板 = 内容策划 + 实拍固定片段 + 验证过的提示词组合，约 1~2 人天。M1 上线需要 20~30 个首发模板，必须配套：

- **admin 模板编辑器**（storyboard/槽位/变量的可视化编排 + 试渲染），与 M1 并行排期（M1.5）；
- 模板生产责任人与验收标准（每个模板真实出片验收，不上未验证模板）。

## 3. 创作链路

### 3.1 正向链路（M1 只上两条）

1. **模板出片**（主链路）：选模板 → 变量预填 + AI 改文案 → 槽位填资产（自动推荐，用户确认/替换）→ 报价确认 → 出片。全程不需要理解「提示词」。
2. **单镜生成**（工具，原子能力的自然暴露）：提示词 + 参考图 → 单段视频；产物可收藏进资产库、可插入项目。
3. ~~智能创作（一句话→AI 脚本+分镜+逐镜提示词）~~ → **降级为「模板槽位的 AI 填充/改稿」，推 M2**。评审结论：完整 AI 导演链路与「不会剪辑要快」的主画像自相矛盾，且模型控质量的次品率会污染口碑；「提示词由 AI 创作」的落点是模板内和改稿里的 AI 辅助，不是独立创作模式。

### 3.2 批量生成（重定义）

- **小程序端首发形态：「一键出 N 变体」**——作品页选一条成片，换开头/换说法/换素材出 3~5 条变体（复用 Remix 机制，无需表格编辑器）。这才是店主的真实批量需求（A/B 试投）。
- **变量表批量**（20 家店各出一条）放 **Web/admin 工作台**（M2）——买单方是代运营，他们开着电脑干活，往小程序塞表格编辑器是自虐。
- 工程上仍是「Batch → 子 Job」两级：允许部分成功（按成功数结算）、批次进度、失败行重跑、错峰提交。
- **批量的工程前置**（不是事后优化）：总装并发闸 + 总装队列与 API 进程隔离（见 §5.6）+ 对供应商与自家总装双限流。

### 3.3 逆向链路（按成本重排优先级）

| 能力 | 成本 | 排期 |
|---|---|---|
| **溯源快照**（模板版本+文案+每镜提示词与资产引用+供应商+任务 id） | 便宜，是一切逆向能力的地基 | M1 必做 |
| **Remix**（作品回草稿换资产/变量出变体） | 便宜（复制草稿） | M1 |
| **整片重跑** | 便宜 | M1 |
| **逐镜重做**（只重生成某一镜再重总装） | 贵：局部替换重总装 + 每镜产物持久留存 + 按镜计费；且 M1 尚无多镜 AI 片 | M2 |

## 4. 供应商适配层（多引擎）

### 4.1 能力抽象（capability，不绑供应商）

| purpose | 状态性 | 说明 | 候选供应商 |
|---|---|---|---|
| `T2V` / `I2V` | 无状态 | 文/图生视频；能力位：首帧、首尾帧、subject reference、时长上限、分辨率 | 火山（Seedance/即梦）、MiniMax（海螺）、可灵、Vidu… |
| `LIP_SYNC` | **有状态**（消费 avatarRef） | 音频驱动数字人口型 | 石榴AI（现网）、火山、MiniMax |
| `AVATAR_TRAIN` / `VOICE_CLONE` | **有状态**（产出 ref） | 形象/声音训练 | 石榴AI、其他 |
| `TTS` | 有状态（消费 speakerRef） | 克隆音合成 | 石榴、火山、MiniMax |
| `IMAGE_GEN` | 无状态 | 分镜参考图/关键帧生成 | 即梦、其他 |
| `SCRIPT_LLM` | 无状态 | 文案/改稿 | 豆包/DeepSeek/Claude |

### 4.2 路由与治理（按状态性分开写）

- **无状态 purpose**（T2V/I2V/IMAGE_GEN/SCRIPT_LLM）：多候选端点（capability + 单价 + 配额 + 健康度），按镜头需求匹配，admin 可配、可灰度、**可故障转移**；
- **有状态 purpose**（LIP_SYNC/TTS/训练）：路由被资产的 `vendorAffinity` 锁定——石榴故障时用石榴训练的数字人只能排队等恢复，**不存在「切到备用供应商」**。给运营的后台文案与告警要如实表达这一点；缓解手段是新训练任务可路由到备选供应商（新资产绑新供应商）；
- 无备选或未配置 → 明确报错不扣费（**禁止静默降级**）；
- 统一异步任务模型：submit→taskId→轮询/回调→**成片立即转存自有存储**（供应商 URL 有时效）；批量场景下优先接供应商回调或做轮询合并，控制对上游 QPS；
- 每次调用记录用量流水（供应商成本 vs 用户积分收入两本账），毛利可观测。

### 4.3 参考注入：三级策略（撤回「等价注入」承诺）

评审对 2026 年主流视频模型能力边界的判断：人物 subject reference 在正脸中近景可用，侧脸/远景/多人劣化；**建筑/门店没有专门 reference 通道**，只能 i2v 首帧，运镜一转就漂；带 logo/包装文字的产品是重灾区。据此写死三级策略，下沉为 `shot.kind` 约束：

| 主体类型 | 注入方式 | 约束 |
|---|---|---|
| **人物**（数字人/真人） | subject reference（选支持该能力的端点） | 模板镜头设计为正脸中近景 |
| **场景**（门店/建筑/环境） | i2v 首帧 | 模板**限制运镜幅度**（缓推/缓摇，禁大幅转场）；「你的店」只在首帧强保真，向用户如实表达 |
| **产品**（含 logo/包装文字） | **只允许实拍素材位（user_footage），禁止 AI 生成** | 用拍摄引导相机页帮用户拍出可用特写 |

配套 pipeline：资产入库时生成标准参考图集（多角度定妆照/裁剪适配）；生成时按端点规格自动装配；质量分级前置（不达标给整改建议而非拒收），不烧钱试错。**M0 按人物/场景/产品三类分别实测验收，不许合并成一个「一致性达标」结论。**

## 5. 工程架构与抽取策略

### 5.1 形态

- **端**：独立微信小程序（新 AppID）；保留移动 H5 通道用于内测（注意：H5 同样需要 ICP + 算法备案，**兜不了备案的底**，只兜「小程序类目审核慢」的底）。
- **服务端**：独立 BFF（登录态、钻石钱包、订单、通知、AI 改稿网关）+ AIStar 生成底座（资产、模板、任务编排、供应商网关、总装）。BFF 与底座间 service token + externalOwnerId 隔离（沿用现行契约）。
- **总装管线**：TTS → 并发生成各镜 → ffmpeg 总装（拼接、字幕、BGM、响度归一、AI 标识）→ 质检门 → 入库出片。

### 5.2 现状事实底座（2026-08-19 摸底）

- 快拍现为军师分包 `app/weapp-native/packages/video/`（14 页），已生产上线；链路：小程序 → 军师 BFF（`server/src/routes/video.ts` + `services/video/`）→ AIStar Clip 域 → 石榴 AI。**供应商只有石榴一家，纯轮询无回调。**
- **前端拆分成本低（当初刻意设计）**：`host.js` 唯一宿主耦合点、样式自包含、`model.js` 零 `wx.*`、mock/bff 双模式。债：12 个页面直接 `require('services/share')` 绕过 host.js 须先收口；需自带 `native-icon`、`login-sheet` 组件。
- **服务端拆分成本高**：BFF 依赖军师七个子系统（用户表、`CreditLedger`、LLM 网关、审核、审计、`FeatureFlag` 定价、调度与订阅消息）。
- **主数据在 AIStar MySQL**（`clip_*` 四表 + `dap_avatar/dap_voice`），按 externalOwnerId 隔离；军师库只有三张钱表。`shared/contracts.d.ts:2647-2910` 的 30+ 个 `Clip*` 类型可整段搬走。
- **底座真实可复用面（评审校正，勿高估）**：石榴口播链、ffmpeg 总装（`ClipAssemblyService` 507 行）、hold/settle/心跳/reaper 骨架、领域类型。**全新要建**：storyboard/assetSlots 模板引擎（现有 `ClipTemplateService` 仅 116 行、本质是片尾管理）、T2V 多供应商网关（一个 T2V 供应商都没接过）、参考图 pipeline、OSS/STS 体系（**现状 FileStorageService 是本地盘 + local-fake CdnUploader**）、Batch。
- **部署余量红线**：军师生产宿主机 4C/7.3G 无 Swap，出过被 Clip 部署残留打挂的事故，不具备再常驻服务的余量；AIStar 生产在独立机 47.98.162.120，两机已同 VPC。
- **未随拆分消失的上线闸**：媒体审核现为 bypass 旁路、四平台代发未接、深合备案/类目未办、真机扣费幂等未验收。

### 5.3 抽取策略：B 为主，A 吸收为合规先遣

| 方案 | 内容 | 结论 |
|---|---|---|
| A. 只换壳 | 新 AppID 壳 + 军师 BFF | 不作为终态，但**吸收为 M0.5 合规先遣壳**（见分期）——新 AppID 注册/类目/备案/首次提审周期以月计且不可控，必须用最小壳尽早把审核往返跑起来 |
| B. **独立 BFF + 共用生成底座（终态）** | 新建轻量 BFF；AIStar 继续作生成底座并扩多供应商网关 | 推荐。边界铁律：**多供应商网关与参考图 pipeline 做成 AIStar 的新模块旁路，不许为新产品重构正在跑生产的 clip 石榴链** |
| C. 全新后端 | 生成底座重写 | 不推荐 |

关键动作：

- 军师内快拍分包降级为「跳转独立小程序」入口位；回填主包三处反向依赖（`services/api.js` videoWorks、锦囊 `clipWorks` 混排、订阅消息落地页路径）。注意 `wx.navigateToMiniProgram` 需用户主动触发+确认弹窗、**登录态带不走**——老用户跳过来是冷启动，入口页要设计「军师老用户认领」引导，不能只放一个跳转按钮；
- **待拍板第 0 条：新 AppID 的注册主体。** unionid 关联的前提是两个小程序绑同一微信开放平台账号；若注册在新主体下，认领式迁移直接不成立，且不同主体间跳转还有关联要求。此决策前置到 M0；
- 数据迁移：按 unionid 认领式迁移（AIStar 侧建 **ownerId 双向映射表**支撑灰度双跑期——直接改 externalOwnerId 会让老入口立刻读不到资产）；供应商训练引用直接复用不重训；
- **切流窗口**：在途 `video_credit_hold` 与进行中任务处理方案——切流前冻结旧入口新提交，存量任务由军师侧结算完再迁；
- 钱包独立核算不与军师混池；老用户给一次性迁移礼包而非打通钱包；
- 新 BFF 部署到 AIStar 所在机或新机，**不加军师宿主机负载**；两机走 VPC 私网回源；
- 微信合法域名提前配置：request（新 BFF 域名）+ uploadFile（OSS）。

### 5.4 任务可靠性（异步生成的铁律）

- 计费三段式：提交 hold → 全部成功 settle → 任一失败 release；批量按成功数结算；
- 幂等：clientRequestId 属主内唯一，超时结果可查证、未确认前不退积分；
- 心跳 + stale reaper：进程重启不产生永久卡死任务；
- 任务可离开：出片完成用订阅消息拉回。**订阅消息额度设计**：训练完成/出片完成/审核驳回竞争一次性订阅授权，按「出片完成 > 训练完成 > 驳回」定优先级，复用军师现成经验。

### 5.5 媒资与上传

- 大文件端上**直传 OSS**（STS 临时凭证），BFF 只收元数据回执。**前提是先做存储迁移**：现状是本地盘，需先建 OSS 体系并迁移存量媒资。安全设计：
  - STS 按 uid 前缀限定路径 + 限 content-type + 限大小；颁发频控防薅存储；
  - **回执不可信**：服务端 HEAD 验证 key 存在/大小 + 过机审后才置可用（防直传绕审核）；
  - OSS bucket CORS + uploadFile 合法域名 + https；
- 转码规范：入库统一 H.264 + AAC + faststart，720×1280 基线（低端 Android 兼容）；
- 资产真值是 OSS key，URL 出 wire 时签名派生；
- 审核链：素材机审 → 成片机审 → 抽检人审；fail-closed 是铁律，但必须配**机审配额水位告警 + 人工放行通道**，否则配额耗尽 = 整站停摆事故。

### 5.6 总装管线规模化（批量的前置工程）

ffmpeg 总装是 CPU 密集型（1 分钟 720p 约 1~2× 实时），当前与 API 同进程同机。批量上线前必须：

1. 总装并发闸（信号量 2~3）；
2. 总装队列与 API 进程隔离（至少独立进程，目标独立容器/机器）;
3. 批量错峰：对供应商 QPS 与自家总装双限流。

## 6. 小程序端设计

### 6.1 信息架构（5 tab）

```
首页(模板+灵感流) | 资产 | ＋创作(中央凸起) | 作品 | 我的
```

- 首页：继续上次 + 数字人状态卡（未创建→引导，同时提供**公共数字人「先试试」**入口）+ 模板分类流；
- 资产：数字人与声音卡片（训练状态）、素材网格（标签筛选）、（M2）品牌包；
- 创作：两入口（用模板 / 单镜生成）；
- 作品：生成中(进度) / 已完成，变体组视图。

### 6.2 关键页面

- 分镜确认页：逐镜列表 = 文案 + 生成方式标签（口播/AI生成/我的素材/固定）+ 缩略图 + 参考资产 chips；顶部实时价格条（切换生成方式价格即时变化）；
- 出片确认页：时长、明细报价、AI 标识声明；报价以服务端权威价为准（端上估价仅供即时反馈，提交回传权威价、变价 409 不扣费——沿用现行铁律）；
- 数字人克隆向导：拍摄要点 + 授权声明 + 训练进度 + 训练期间可先用公共数字人；
- 拍摄引导相机页：构图框 + 要点提示，服务素材质量分级；
- 一键 N 变体页：选成片 → 勾选变体维度（换开头/换说法/换素材）→ 批次进度。

### 6.3 机型与平台适配

- 安全区：自定义 tabBar 用 padding-bottom + env(safe-area-inset-bottom)；
- 竖屏 9:16 预览卡片显式宽高（WXSS 无 aspect-ratio）；
- 视频播放：H.264 兼容矩阵，iOS/Android 双真机回归（工具 ≠ 真机）；
- 上传：分片直传 + 断点续传 + 弱网重试；录音/相册权限失败态引导；
- 长列表分页 + 懒加载，setData 只写视图字段；轮询 onUnload 清理；
- 低端机降级：预览图代替视频自动播放、关闭复杂动效。

## 7. 合规（上线前置，时序是第一风险）

1. **备案与类目必须 M0 启动**：微信对 AIGC 类小程序要求提供算法备案号/深度合成备案回执才给过审——没有备案号可能连类目都开不了，「并行推进」糊弄不过去。备案主体、与供应商的备案分工（他们备算法我们备服务，还是各自备）写进商务合同；
2. **AI 生成内容标识**（《人工智能生成合成内容标识办法》2025-09-01 施行）：显式标识（成片可见水印/提示）+ 隐式标识（元数据）+ **服务协议明示**。注意隐式标识在「保存相册→上传抖音」链路里必丢，实际可执行的是显式水印 + 协议声明 + 发布平台侧申报；
3. **身份类资产授权**：本人声明 + 授权快照 + 可随时删除（连带供应商侧）；供应商通常要求平台持有最终用户授权凭证，商务条款里写清连带责任分工；未成年人拒绝采集；
4. **内容安全**：素材与成片双机审 fail-closed + 配额告警 + 人工放行通道（§5.5）。

## 8. 商业化与成本模型

- 个人：克隆一次性费（首次可免/低价引流）+ 出片按条/按积分；会员订阅含月度出片量；
- 企业/代运营：批量出片包（阶梯价）→（后期）组织席位订阅；
- **单片成本结构表是 M0 硬出口**（评审指出原稿空转）：TTS（按字符）+ 口播段（按分钟）+ T2V 段（按 5~10 秒段计价）+ 机审（视频按分钟）+ 存储流量。一条 6 镜片成本量级可能 ¥5~15——直接决定「免费首片」获客成本可不可承受、定价下限在哪；
- 成本护栏：报价即成本可见（价格条）、单账号日限额、批次并发闸、供应商用量双账本核毛利；
- 定价数据全部走运营后台配置，代码不落定价常量。

## 10. 主要风险

1. **合规时序**（第一风险）：备案/类目周期以月计且不可控 → M0b 抢跑 + M0.5 先遣壳；
2. **参考一致性达不到宣传**：三级策略如实承诺 + M0 分类实测硬门；
3. **成本失控**（批量 × 视频生成 = 烧钱放大器）→ hold/settle + 日限额 + 并发闸 + 成本结构表先行；
4. **供应商单点**（有状态资产锁定石榴）→ 新训练可路由备选供应商；商务谈判中把 SLA/删除政策/授权连带写进合同；
5. **克隆滥用与肖像权** → 授权闸门 + 抽检 + 快速下架删除通道；
6. **抽取期两边打架** → 切流冻结窗口 + ownerId 双向映射 + 明确下线军师内旧入口的时间表。
